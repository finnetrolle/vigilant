# VIG-05-04: E2E-тест отмены клиента

**Статус:** Ready for implementation
**Epic:** [EPIC-05](../../epics/epic_05_v0_hardening.md)
**Ветка:** Верифицируемость поведения > отмена клиента
**Зависит от:** нет
**Блокирует:** нет
**Оценка:** 2-4 инженерных дня
**Уверенность:** Medium

## Результат

Отключение или отмена со стороны клиента закрывает или отменяет
upstream-запрос (`CONC-04`, критерий готовности v0 №3). Поведение подтверждено
автоматизированным E2E-тестом, а не предположением о propagation в Armeria.

## Требования

`CONC-04`, критерий готовности v0 №3.

## Критерии готовности

- [ ] E2E-тест: клиент начинает streaming-ответ, обрывает соединение после
  первого чанка; upstream фиксирует отмену (callback отмены/закрытие со стороны
  gateway) в течение заданного окна.
- [ ] Частично полученный клиентом контент корректен и упорядочен.
- [ ] Тест детектирует отсутствие propagation: если upstream не видит отмену,
  тест падает.
- [ ] Если текущий pass-through не пропагирует отмену, в этой же issue вносится
  минимальный production-fix (подписка на отмену клиентского response с
  отменой upstream-запроса) с RED-фазой по TDD-процессу проекта.
- [ ] Отмена не оставляет висящих ресурсов: тест на несколько
  последовательных отмен без утечки соединений (по возможности фикса).
- [ ] `./gradlew build` проходит.

## Не входит

Отмена plugin-вызовов (плагинов ещё нет), timeout-based отмена (VIG-05-05),
аудит отменённых запросов.

## Рекомендуемые решения внутри issue

- Отправной пункт проверки: `HttpRequestAbortedException`/`whenRequestCanceled`
  на стороне тестового upstream и `HttpResponse.abort()` на стороне клиента.
- Сначала написать RED-тест, ожидающий отмену upstream; по результату решить,
  нужен ли production-fix.
