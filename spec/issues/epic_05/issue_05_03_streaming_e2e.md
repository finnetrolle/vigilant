# VIG-05-03: E2E-тест стриминга без буферизации

**Статус:** Done
**Epic:** [EPIC-05](../../epics/epic_05_v0_hardening.md)
**Ветка:** Верифицируемость поведения > стриминг без буферизации
**Зависит от:** нет
**Блокирует:** нет
**Оценка:** 2-3 инженерных дня
**Уверенность:** Medium

## Результат

Автоматизированный E2E-тест доказывает, что gateway передаёт streaming-ответ
без полной буферизации: первый байт приходит клиенту до завершения ответа
upstream, все чанки доставляются в порядке следования, полный контент
совпадает. Текущие тесты используют только `aggregate()` и буферизацию не
исключают.

## Требования

`PROXY-01`, критерий готовности v0 №2.

## Критерии готовности

- [x] Upstream отдаёт ответ чанками с контролируемыми задержками между ними.
- [x] Тест фиксирует time-to-first-byte у клиента раньше отправки последнего
  чанка upstream (upstream ещё не завершил ответ).
- [x] Чанки доставляются клиенту в порядке отправки; итоговый контент
  идентичен.
- [x] Вариант с SSE-подобным контентом (`text/event-stream`) проходит тот же
  сценарий.
- [x] Тест детектирует агрегацию: если между gateway и клиентом появляется
  полная буферизация (первый байт только после последнего чанка), тест падает.
- [x] Класс теста следует существующему E2E-стилю `BypassProxyServiceTest`
  (реальные Armeria server'ы на ephemeral ports).
- [x] `./gradlew test --tests "io.vigilant.gateway.BypassProxyServiceTest"`
  проходит (или тест размещён в новом классе и `./gradlew build` проходит).

## Не входит

Изменение production-кода (issue - тестовая верификация уже заявленного
поведения; если тест вскрывает реальную буферизацию, фикс выделяется в
отдельную issue), backpressure-метрики, отмена (VIG-05-04).

## Рекомендуемые решения внутри issue

- Upstream с `StreamingHttpService`/writer, отправляющий чанки по расписанию.
- Клиент читает response как поток и записывает моменты получения чанков.
