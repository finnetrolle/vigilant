# VIG-05-01: Стабильная proxy-ошибка при сбое upstream

**Статус:** Ready for implementation
**Epic:** [EPIC-05](../../epics/epic_05_v0_hardening.md)
**Ветка:** Надёжность proxy > стабильные proxy-ошибки upstream
**Зависит от:** нет
**Блокирует:** нет
**Предпочтительный порядок (не блокировка):** раньше issues явных таймаутов и OTel metrics
**Оценка:** 2-3 инженерных дня
**Уверенность:** High

## Результат

Клиент получает стабильную, задокументированную proxy-ошибку, когда upstream
недоступен, не отвечает за timeout или отвечает некорректным HTTP; внутренние
исключения Armeria, имена классов и stack trace до клиента не доходят.
Корректные HTTP-ответы upstream (включая 4xx/5xx) по-прежнему передаются без
интерпретации.

## Требования

`PROXY-03`, критерий готовности v0 №4.

## Критерии готовности

- [ ] Connection failure (отказ соединения, unknown host) - единый стабильный
  ответ, рекомендованный baseline: `502 Bad Gateway` со стабильным телом
  (JSON- или text-формат фиксируется в issue) и без внутренних деталей.
- [ ] Timeout upstream - отдельная стабильная ошибка, рекомендованный baseline:
  `504 Gateway Timeout` с тем же форматом тела.
- [ ] Класс ошибки различим клиентом (статусом или стабильным кодом в теле) и
  различим для метрик (transport error vs timeout).
- [ ] Статус и тело корректного HTTP-ответа upstream передаются без изменений -
  существующий тест прозрачности продолжает проходить.
- [ ] E2E-тест через реальный Armeria upstream: мёртвый upstream (закрытый
  порт) и зависший upstream (не отвечает в течение таймаута).
- [ ] Ошибка логируется структурно, без тел запросов/ответов и auth headers.
- [ ] `./gradlew build` проходит.

## Не входит

Retry, circuit breaker, кастомные ошибки для конкретных провайдеров, изменение
поведения при корректных ответах upstream, конфигурируемость таймаутов
(VIG-05-05).

## Рекомендуемые решения внутри issue

- Статусы: `502` для transport errors, `504` для timeout.
- Тело: минимальный стабильный JSON без текста исключения, например
  `{"error": "upstream_unavailable"}` / `{"error": "upstream_timeout"}`.
- Механизм: обработка failure будущего `upstream.execute(...)` без агрегации
  тела успешных ответов.
