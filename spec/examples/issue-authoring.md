# Примеры authoring: Low и High

Это два независимых учебных предложения по
[каноническому шаблону](../ISSUE_TEMPLATE.md), не active work items и не
разрешение менять runtime. ID им не выделены. Классификацию и readiness
проверять по [нормативному owner](../WORK_ITEMS.md#risk-based-readiness).

## Low: локальное исправление ссылки

- **Статус:** Ready for implementation
- **Архитектурный риск:** Low - исправляется только опечатка в локальной
  navigation link, без изменения требований, runtime или обязанностей deployment.
- **Зависит от:** нет

### Результат

В учебном входе ссылка на configuration в `docs/README.md` ошибочно ведёт на
`configuraton.md`. Читатель переходит к существующему `configuration.md`.

### Context sources

- `docs/development.md#проверка-каталога-и-ссылок`

### Критерии готовности

- [ ] Target одной ссылки равен literal `configuration.md`, а её label сохранён.
- [ ] Переход из `docs/README.md` открывает документ configuration.

### Проверки

Diff одной ссылки и `rtk proxy ./gradlew validateWorkItems`.

### Не входит

Редактура configuration contract и других документов.

## High: сохранённое подтверждение приёма

- **Статус:** Draft
- **Архитектурный риск:** High - предлагается persistence и новый public
  contract подтверждения сохранения записи.
- **Зависит от:** нет

### Scope lock

1. **Наблюдаемый продуктовый результат:** отправитель предложенной службы приёма
   отличает запись, сохранённую после перезапуска, от не принятой.
2. **Минимальное достаточное решение:** один локальный журнал с восстановлением
   подтверждённых записей после перезапуска одного процесса.
3. **Обязательные свойства результата:** ACK выдаётся только после устойчивого
   сохранения; после ACK запись читается после restart; storage failure до ACK
   возвращает явный отказ без успешного подтверждения.
4. **Явные non-goals:** репликация, кластерный failover и integration с gateway.
5. **Более сложные альтернативы:** distributed broker отклонён из-за отсутствия
   multi-node требования; внешний database service отклонён из-за отсутствия
   запросов и shared access в этом учебном результате.
6. **Условие пересмотра:** возникает требование сохранить доступность после
   потери узла или обслуживать несколько writer processes.
7. **Подтверждение:** не получено; владелец решения не подтвердил необходимость
   persistence и ACK contract. Предложение остаётся `Draft`.

### Context sources

- `spec/WORK_ITEMS.md#risk-based-readiness`
- `spec/ISSUE_TEMPLATE.md#scope-lock`

### Критерии готовности

- [ ] После получения ACK, остановки и запуска процесса чтение возвращает
  исходную запись, сравниваемую с независимым literal input.
- [ ] Storage failure перед сохранением наблюдается как отказ без ACK.

### Проверки

При будущем согласовании: реальные restart и storage-failure сценарии на
публичной границе службы. В этом документационном примере runtime отсутствует,
эти сценарии не запускались.

## Ручная проверка authoring behavior

Оценивать содержание предложений, затем сравнивать допустимый статус с указанным
в примере. Это semantic review, не автоматическое решение validator.

| Независимый вход | Наблюдение по правилам readiness |
|---|---|
| Low: только literal link typo, один локальный результат, ясные criteria/non-goals | Допустим `Ready for implementation`; уровень и одна причина достаточны, approval и пустого scope lock нет. |
| High: persistence/ACK с одними техническими criteria, до заполнения lock | Только `Draft`: полнота технических проверок не заменяет решение о необходимости механизма. |
| High: показанные части 1-6 заполнены, часть 7 не подтверждена | Только `Draft`: отсутствие owner confirmation видно в самом предложении. |
| High: впоследствии все семь частей заполнены, получено реальное подтверждение именно этого scope | Readiness gate допускает переход при выполнении остальных правил issue; этот учебный документ не утверждает, что подтверждение уже получено. |

Дополнительно пройти каждую строку классификации у owner по отдельности:
resource owner, mandatory configuration, persistence, public contract,
deployment, packaging, связь runtime subsystems и неоднозначность направляют
в `High`; локальный случай без этих признаков направляется в `Low`.
