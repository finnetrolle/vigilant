# Обнаружение PII

## Роль при исполнении

Точные правила принадлежат [Fast PII contract](../spec/requirements/fast-pii.md),
оконная обработка - [windowed inspection](../spec/requirements/windowed-inspection.md).
Этот документ описывает их подключение к runtime.

`fast-pii` - встроенный детерминированный детектор для текстовых фрагментов
request и ordinary JSON/SSE response OpenAI Chat Completions. Он работает внутри процесса
без сетевого ввода-вывода, моделей машинного обучения и динамической загрузки
модулей. Система запускает его в ограниченном пуле CPU вне цикла событий
Netty.

Детектор не принимает исходные HTTP или JSON и не выбирает поля протокола. Эту
работу выполняет [анализатор Chat Completions](openai-chat-completions.md).
Каждое текстовое поле проверяется независимо.

## Поддерживаемые категории

| `PiiType` | Основание распознавания | Стабильный идентификатор распознавателя |
|---|---|---|
| `EMAIL_ADDRESS` | Ограниченный синтаксис адреса электронной почты, проверка домена и границ | `fast.email_address` |
| `PHONE_NUMBER` | Поддерживаемые формы российских телефонных номеров и локальная проверка | `fast.phone_number.ru` |
| `PAYMENT_CARD` | Допустимые разделители, длина и контрольная сумма Луна | `fast.payment_card.luhn` |
| `IP_ADDRESS` | Строгий локальный анализатор IPv4 и IPv6 без DNS | `fast.ip_address` |
| `IBAN` | Реестр длин по странам и проверка по модулю 97 | `fast.iban` |
| `RU_INN` | Только 12 цифр ИНН физического лица и две контрольные цифры | `fast.ru_inn` |
| `RU_SNILS` | Формат, контрольная сумма и ограниченный контекстный запасной вариант | `fast.ru_snils` |
| `RU_PASSPORT` | Серия и номер с обязательным ограниченным контекстом | `fast.ru_passport` |
| `RU_OMS` | Формат, контрольная сумма и ограниченный контекстный запасной вариант | `fast.ru_oms` |

Версия распознавателя меняется при наблюдаемом изменении принимаемых или
отклоняемых входных данных, смещений, силы свидетельства или справочных данных.
Версия справочных данных IBAN входит в версию распознавателя.
Точные layouts, separators, context windows, false-positive boundaries и
текущие версии перечислены в [полной taxonomy](../spec/requirements/fast-pii.md#taxonomy).

`fast.ip_address@1.2.0` распознаёт IPv4 перед корректным decimal port и
последующим текстом, например `connect 192.0.2.1:443 now`. Finding покрывает
только адрес. REQUEST и ordinary JSON/SSE RESPONSE используют этот finding
в существующих ALLOW/MASK/BLOCK policies: ALLOW сохраняет исходные bytes,
MASK меняет адрес и сохраняет port/prose, BLOCK возвращает safe policy error.
Request marker подчиняется существующему shortening, response marker -
[правилам response masking](response-masking-headers.md). Обычное terminal
colon сохраняет значение пунктуации; signed и invalid port не открывают
валидный IP prefix.

## Контракт срабатывания

Срабатывание содержит только:

- `type`;
- полуоткрытый диапазон смещений `[startUtf8, endUtf8)` в байтах исходного
  декодированного фрагмента;
- `confidence`, сейчас всегда равный `null` для детерминированного детектора;
- `evidenceStrength`;
- идентификатор и версию распознавателя.

Совпавший текст, предварительный просмотр и нормализованное чувствительное
значение не возвращаются и не записываются в журнал. Сила свидетельства не
является вероятностью:

- `VALIDATED`: строгий анализатор или контрольная сумма;
- `CONTEXTUAL`: формат вместе с обязательным ограниченным текстовым контекстом;
- `FORMAT_ONLY`: достаточно характерный формат без контрольной суммы или
  контекста.

Адаптер политик выполняет полное сканирование каждого фрагмента и переносит
точные метаданные в результат политики. Аудит сохраняет только агрегированные
счётчики, но не отдельные смещения и расположения.

## Входные данные, Unicode и оконная обработка

Один прямой вызов детектора принимает не более `1 MiB` в UTF-8. До сканирования
он линейно проверяет суррогатные пары UTF-16 и точный размер UTF-8 без полного
копирования в `ByteArray`. Недопустимый Unicode и превышение размера при прямом
вызове дают типизированные ошибки детектора без полезной нагрузки в сообщении.

Фрагмент запроса может быть больше `1 MiB`. Система не обрезает и не отклоняет
его только из-за ограничения детектора. PII-free
`WindowedInspectionExecutor` планирует UTF-8-safe ownership cores, переносит
смещения и агрегирует результат. Тонкий `WindowedFastPiiExecutor` предоставляет
ему вызов `FastPiiDetector`, semantic identity, сравнение метаданных,
канонический порядок и следующие версионированные возможности:

- максимальное окно `1 048 576` байтов UTF-8;
- максимальный evidence span `4 096` байтов, включающий candidate и required
  lookarounds; из него выводится context budget `4 095` байтов с каждой стороны core;
- безопасные границы UTF-8;
- перенос смещений обратно в исходный фрагмент;
- детерминированное удаление повторных срабатываний в перекрытии окон.

Если детектор не предоставляет конечную гарантированную границу диапазона
свидетельства, оконная обработка больших фрагментов для него запрещена.
Source limits/defaults описаны в [configuration](configuration.md), а product
targets остаются в [MVP NFR](../spec/MVP_NON_FUNCTIONAL_REQUIREMENTS.md#conc-01-request-bounds-и-response-heap-lifecycle).
Windowing не заменяет эти ограничения. [Coverage](requirements-coverage.md#pii-и-windowing)
отмечает неподтверждённые части current capability proof и boundary corpus.

Для IPv4 с port достаточен evidence span не более 29 UTF-8 bytes:
15 bytes адреса, colon и до пяти digits, плюс по одному code point границы
слева и справа (до четырёх bytes каждый). Это укладывается в текущий E=4096;
численные параметры и версия capability не меняются. Проверки IP port
пересекают ownership boundary внутри адреса, перед colon и внутри port с
Unicode padding и независимыми global offsets. Эти случаи не закрывают
остальные gaps полной window matrix.

## Детерминизм и отмена

Прямой `PiiDetector.detect` сортирует по фиксированному порядку типов, затем
по смещениям и recognizer ID. Windowed aggregate, включая его direct path,
сортируется по global start/end, type name, recognizer ID/version. Policy
adapter сохраняет именно этот global order и всегда делает полный scan всех
типов; внутренний `enabledTypes` не является administrator policy selector.
Результат детерминирован для одинаковых входа, параметров и версий.

Детектор неизменяем и безопасен для параллельного использования. Он проверяет
прерывание потока между распознавателями и кандидатами и отменяет работу без
частичных срабатываний. Уровень приложения владеет сроком, ограниченной очередью
и отменой задачи.

## Свидетельства качества

Обычная задача `test` включает канонический синтетический набор положительных
и сложных отрицательных примеров, а также контрактные тесты и тесты свойств.
Читаемый человеком отчёт создаётся командой:

```bash
./gradlew piiQualityReport
```

Внешняя оценка RedMadRobot запускается отдельно и не меняет поддерживаемый
контракт:

```bash
./gradlew redMadRobotPiiBenchmark
```

Базовый тест JMH запускается командой:

```bash
./gradlew piiJmhBaseline
```

Ориентированная на продукт квалификация качества фиксирует точные и ослабленные
метрики относительно источника, неизменяемое разбиение и парные свидетельства
производительности. Отдельный версионированный эталон добавляет IP-literal host
внутри размеченного URL независимо от detector и нормализует целые исходные
метки IPv4:port до address-only spans. Source/product gold сохраняется; версия
эталона и число преобразований публикуются. Baseline и current пересчитываются
на этом общем эталоне; исходные метрики сохраняются, все числовые пороги действуют.
Эти отчёты измеряют конкретную таксономию и набор данных и
не доказывают качество семантического NER вне перечисленных форматов.
Pinned counts/split, product-aligned adjustments, privacy suppression,
qualification commands и полная test matrix находятся в
[development guide](development.md#pii-quality). Они не подтверждают новый
enforcement PERF-01 без соответствующего run.

## Ограничения

Текущий детектор не распознаёт:

- ФИО и отдельные части имени;
- свободные почтовые адреса;
- даты рождения;
- произвольные банковские счета вне IBAN;
- ключи API, учётные данные и общую таксономию секретов;
- внедрение инструкций и jailbreak;
- PII, распознавание которых требует семантического вывода ML или LLM;
- маскировку с помощью гомоглифов Unicode, символов нулевой ширины или
  транслитерации вне явно поддерживаемых правил.

`CLEAN` detector adapter означает отсутствие findings в поддержанной surface;
protocol inspection gaps учитывает отдельный слой. Это не доказывает отсутствие любых
PII или секретов в человеческом смысле.

Явно выбранная policy допускает находку, маскирует free text или блокирует
request по [контракту enforcement](policies.md). Structural MASK блокирует
весь request; technical failure включённой проверки даёт safe 503. Покрытие
целевого MVP и оставшиеся пробелы перечислены в
[карте покрытия требований](requirements-coverage.md).
