# Покрытие требований документацией и реализацией

## Назначение

Этот документ переводит нормативные требования из `spec/` в читаемую карту
текущего продукта. Он отвечает на три вопроса:

1. Что действительно работает в текущем репозитории?
2. Где это поведение документировано?
3. Какая часть целевого MVP и Stage 1 ещё не реализована?

Нормативные формулировки остаются в следующих документах:

- [Функции MVP](../spec/MVP_FUNCTIONS.md);
- [Нефункциональные требования MVP](../spec/MVP_NON_FUNCTIONAL_REQUIREMENTS.md);
- [Функции Stage 1](../spec/STAGE_1_FUNCTIONS.md);
- [Функции вне области продукта](../spec/OUT_OF_SCOPE_FUNCTIONS.md).

Статусы здесь не заменяют [`WORK_ITEMS.md`](../spec/WORK_ITEMS.md). Они имеют
следующие значения:

- `Работает` - наблюдаемый контракт реализован в текущей поддерживаемой области;
- `Частично` - реализована полезная часть или основа, но требование целиком ещё
  не выполнено;
- `Не реализовано` - текущая исполняемая система не предоставляет возможность;
- `Соблюдается` - функция намеренно остаётся за границей продукта.

## Функциональные требования MVP

| ID | Статус | Текущий факт и документация |
|---|---|---|
| `MVP-01` | Частично | Запрос Chat Completions проверяется до передачи первого байта вышестоящему серверу. Контроль вызовов инструментов и ответов модели отсутствует. [Контракт протокола](openai-chat-completions.md), [контракт исполнения](runtime-contract.md) |
| `MVP-02` | Частично | Для каждой политики заданы срок и реакция на ошибку, но при запуске разрешается только теневое решение `ALLOW`; настраиваемые режимы fail-closed и передачи оператору отсутствуют. [Политики](policies.md) |
| `MVP-03` | Не реализовано | Нет точки контроля выполнения инструментов или промежуточного слоя SDK. |
| `MVP-04` | Частично | Анализатор извлекает текстовые аргументы инструментов как фрагменты, но не контролирует фактический вызов инструмента. [Карта полей протокола](openai-chat-completions.md#что-передаётся-детектору) |
| `MVP-05` | Не реализовано | Результат инструмента не проверяется перед передачей агенту. |
| `MVP-06` | Не реализовано | Нет настраиваемого безопасного ответа о блокировке, поскольку принудительное применение решений не активно. |
| `MVP-07` | Не реализовано | Детектор внедрения инструкций и jailbreak отсутствует. |
| `MVP-08` | Не реализовано | Нет детектора косвенного внедрения инструкций и интеграции с поиском или файлами. |
| `MVP-09` | Не реализовано | Нет настраиваемых оператором детекторов на основе регулярных выражений, чёрных и белых списков. |
| `MVP-10` | Частично | Структурированные PII распознаются только во входных текстовых фрагментах Chat Completions. Секреты, ответы модели и результаты выполнения инструментов целиком не покрыты. [Обнаружение PII](pii-detection.md) |
| `MVP-11` | Не реализовано | `MASK` и `REMOVE` есть только в доменной модели; запуск и транспорт запрещают их. [Политики](policies.md#выполнение-детекторов-и-реакции) |
| `MVP-12` | Не реализовано | Ограничение тем и предметных областей отсутствует. |
| `MVP-13` | Частично | Механизм политик строит неизменяемое детерминированное решение, а аудит хранит безопасные ссылки на политики и детекторы и итог решения. Универсальный внешний API решений ещё не опубликован. [Архитектура](architecture.md), [наблюдаемость](observability.md) |
| `MVP-14` | Частично | Сопоставление поддерживает URL, модель, фазу, пользователя, группу и глобального субъекта. Development/test Dummy Bearer boundary передаёт configured normalized user/groups; real production identity пока отсутствует. Измерения арендатора, приложения, агента, инструмента, операции и ресурса отсутствуют. [Политики](policies.md#контекст-сопоставления) |
| `MVP-15` | Не реализовано | Есть тестовые наборы детекторов и задачи оценки качества, но отсутствует операторская среда проверки политики до публикации. |
| `MVP-16` | Работает | Глобальная политика PII для запросов работает только в теневом режиме и всегда сохраняет исходный запрос. [Политики](policies.md#текущий-контракт), [контракт исполнения](runtime-contract.md#shadow-pii-decision) |
| `MVP-17` | Не реализовано | Процесс подтверждения человеком и передачи оператору отсутствует. |
| `MVP-18` | Работает | Версионированное решение политики и детектора сохраняется в принадлежащем приложению долговечном WAL. Контракт ready/ack позволяет внешнему Collector выполнить долговечную доставку, но сам Collector не входит в поставку. [Наблюдаемость](observability.md#guaranteed-minimum-audit-trail), [передача файлов](audit-collector-file-handoff.md) |
| `MVP-19` | Работает | Схемы аудита, журналов и ошибок исключают полезную нагрузку, совпавший текст, учётные данные, идентификаторы пользователей, расположения и обратимые хеши. [Наблюдаемость](observability.md#безопасность-данных) |
| `MVP-20` | Частично | Интеграция через `base_url` работает только для проверки запросов Chat Completions; ответ передаётся сквозным образом, а другие API OpenAI отклоняются. [Контракт протокола](openai-chat-completions.md) |
| `MVP-21` | Не реализовано | Промежуточный слой SDK отсутствует. |

Целевой MVP нельзя считать полностью реализованным только потому, что достигнут
производственный этап теневой проверки PII. Текущий продукт является первым
ограниченным этапом защитных механизмов, а не всей областью `MVP-01..21`.

## Правило обновления

Любая производственная задача, меняющая покрытие требований, должна в одном
наборе изменений обновить:

1. требование или спецификацию-владельца и статус рабочего элемента;
2. точный документ по исполнению, конфигурации или протоколу;
3. эту карту покрытия;
4. UML-диаграмму 2.0, если изменились компонент, последовательность, жизненный
   цикл или состояние;
5. версионированные свидетельства только после фактического динамического
   прогона.
